size is not rows scanned. Both aggregates execute before the publisher's
unchanged-evidence/noop check. The staging scheduled handler calls this
publisher on every tick while ACTIVE and provisioned with a verification key.
The live schedule was confirmed as `* * * * *`.

## Immediate containment

At 2026-09-28T12:58:09Z, changed only
`quant-platform-ingestion-premium-staging` Cron to `15 * * * *` via API and
verified it by GET. This configuration change is mirrored in Wrangler.
No Worker code, production schedule, data, signed evidence or DLQ was changed.
All operations sharing this staging tick, including controlled acquisition
and recovery, now run hourly. This is a deliberate latency tradeoff, not
an instruction to restart completed controls or expired jobs.

Expected baseline reduction is approximately 60x, not yet a measured result.
Allow Cron propagation and analytics delay before comparing complete hours.
Do not restore minute scheduling until the projection full-scan path has
been addressed and its read cost measured. Old-source deployments can
restore the old schedule; inspect the live Cron after any such deployment.
