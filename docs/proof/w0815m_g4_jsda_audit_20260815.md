## 1. Critical question

Why does `storage_plane_status` report `jsda.tokyo_repo_rows: 0` while `jsda_tokyo_repo_rates` is dataset **COMPLETE**?

## 2. Root cause (with evidence)

### 2.1 Two different aggregates

| Signal | What it measures | Owner path |
|--------|------------------|------------|
| `tokyo_repo_rows` | `COUNT(*)` on fact table **`jsda_repo_rates`** **on the DB plane being queried** | `data_access/service.py` / MCP `domain.js` `storage_plane_status` |
| Dataset **COMPLETE** | Signed `collection_receipts` + `coverage_segments` evaluation → `dataset_coverage.status` | `storage/coverage_ledger.py` + projection publish |

These are **intentionally independent**. Ops projection publishes **coverage ledgers**, not full JSDA fact backfill to D1.

Code (pre-fix keys unchanged; honesty fields added this wave):

```python
# packages/data_plane/data_access/service.py — storage_plane_status
repo = count("SELECT COUNT(*) AS n FROM jsda_repo_rates")
# ...
"tokyo_repo_rows": repo,
```

Coverage COMPLETE for Tokyo Repo uses single segment `jsda-era-timeseries` (`source_time_series_file` granularity) and requires a **TRUSTED** Ed25519 receipt (`evaluate_segment` / `is_complete_eligible_receipt`). Fact-table emptiness does **not** fail that gate once the receipt is sealed.

Architecture ([`docs/architecture/cf_native_storage_plane.md`](../architecture/cf_native_storage_plane.md)):

- **CF SoT:** D1 = control / evidence / **hot tip** · R2 = **history** (`quant-structured` / raw) · COMPLETE = **receipt-owned**
- Local research SQLite = **mirror / research convenience** — **not** authority, **not** “local SoT”
- High-volume full-history **must not** refill D1

So **`tokyo_repo_rows: 0` on D1 while COMPLETE holds is plane-split, not receipt fraud and not data loss.**

### 2.4 R2 / parse path

| Layer | Tokyo Repo path |
|-------|-----------------|
| Official source | `https://www.jsda.or.jp/shiryoshitsu/toukei/trr/files/trrts.xls` |
| Local raw (governed archive) | `data/raw/jsda/2026/08/11/trrts_*.xls` + index HTML (date-stamped, **not** under `jsda_tokyo_repo_rates/` dataset dir) |
| Parser | `ingestion/jsda/parse.py` → `parse_repo_xls` (xlrd) → wide matrix → `(as_of_date, tenor, rate)` |
| Normalize / fact | `normalize_repo_rates` → table **`jsda_repo_rates`** |
| Governed runner | `ingestion/jsda/repo_archive.py` `run_tokyo_repo_backfill` → signed receipt |
| Staging-only R2 mirror parse | `ingestion/jsda/r2_parse.py` — discovers `raw/jsda/<dataset>/…`, emits **PARSED_STAGING_ONLY**, **never** COMPLETE |

`r2_parse.discover_local_jsda_raw` expects dataset-named dirs (`jsda_tokyo_repo_rates/…`). The production Tokyo Repo seal used the **repo_archive** date-stamped layout under `data/raw/jsda/YYYY/MM/DD/`, so a naive R2-mirror staging walk can show **0 artifacts** for repo while the governed seal path already wrote 30303 facts + TRUSTED receipt. That is a **layout / discoverer mismatch**, not missing sealed data.

## 4. Field coverage audit

### 4.1 `jsda_otc_bond_reference_prices` (local mirror n=**702451**)

Typed columns vs `raw_payload`: **aligned** (payload keys = parser record; normalize dumps full record).

| Field | null/empty % | notes |

| security_code, bond_name, maturity_date, available_at, raw_payload | **0%** | full |
| average/median/high/low price | ~0% (3 nulls) | negligible |

**Residual:** dataset still **PARTIAL** vs inventory **~8781** official archive days (tip-heavy seal; history target 2002-08-02).

### 4.2 `jsda_corporate_bond_transactions` (local mirror n=**156079**, dataset **COMPLETE** 12/12 years, receipt-owned)

Official TORIHIKI CSV is **11 columns**, headerless, e.g.:

```text
publication_label, trade_date, security_code, issuer_name, maturity,
coupon, transaction_type(売り/買い), empty, flag(*), execution_price, execution_yield
```

| Schema column | In official CSV? | null/empty % | typed vs payload |
|---------------|------------------|-------------:|------------------|
| security_code, issuer_name, maturity_date | yes | **0%** | match |
| coupon_rate | yes | **6.3%** | match (source blank) |
| transaction_type | yes (col6) | **20.4%** | empty 2015–2017 + partial 2018; full 2019+ |
| execution_price | yes | **20.3%** | same era pattern as txn_type |
| execution_yield | yes | **0.45%** | match |
| **isin** | **no** | **100%** | schema-superset; absent from payload keys |
| **buyer_counterparty_type** | **no** | **100%** | schema-superset |
| **seller_counterparty_type** | **no** | **100%** | schema-superset |
| **face_value_mil_jpy** | **no** | **100%** | schema-superset |
| **trade_amount_mil_jpy** | **no** | **100%** | schema-superset |
| raw_payload, available_at | — | **0%** | always set |

**Conclusion:** empty counterparty/ISIN/face/amount columns are **not parse loss** — they are **schema columns wider than official source**. Typed fields that exist in source track payload. Era blank `transaction_type`/`execution_price` for 2015–2017 match official file cells (empty before 売り/買い was published).

### 4.3 `jsda_repo_rates` (local mirror n=**30303**; R2 = history SoT; COMPLETE receipt-owned)

All typed fields populated (rate/tenor/rate_type/available_at/raw_payload **0%** null). Payload is `{as_of_date, tenor, rate}` only — by design.
